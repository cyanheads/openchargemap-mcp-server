# 0.1.7 — 2026-08-06

## Added

- **`offset`/`nextOffset` pagination** — `openchargemap_find_stations`, `openchargemap_lookup_reference`, and `openchargemap_get_station_comments` now page past a truncated result instead of stopping at the cap. (#5)
- **`openchargemap_lookup_reference` `source` output field** — `'live'` or `'bundled'`, disclosing whether the served reference data came from a successful startup refresh or the shipped snapshot. (#11)
- **`openchargemap_get_station_comments` `totalComments` output field** — the station's full comment count, independent of the returned page. (#16)

## Changed

- **`openchargemap_find_stations` candidate paging** — `searchPois` fetches a quantized 100/250/500-record candidate page (sized from the caller's window, not `maxresults`) and runs local filters (`minchargepoints`, coordinate sanity) over the whole page before slicing the caller's window out of it. (#5, #8)
- **`openchargemap_find_stations` `totalCount`** — now the count of matches this search retrieved, disclosed as exact or a floor depending on whether the candidate page came back short; the enrichment trailer renders it as "N matching stations retrieved" instead of the framework's default "N total". (#8)
- **`openchargemap_find_stations` `boundingbox`** — rejected as `invalid_location` when supplied alongside a lone `latitude` or `longitude`, instead of silently dropping the stray coordinate. (#17)
- **`openchargemap_lookup_reference` `snapshotDate`** — now reports the vintage of the data actually in memory (the refresh date when `source` is `live`) instead of the bundled snapshot's date unconditionally. (#11)
- **`openchargemap_get_station` `includeComments` description** — discloses that it returns every comment unpaged and points at `openchargemap_get_station_comments` for the paged path. (#5)
- **OCM request** — the inert `minnumberofpoints` query parameter is no longer sent; `minchargepoints` was already enforced locally. (#8)

## Fixed

- **`openchargemap_find_stations` false `no_stations`** — a capped upstream page emptied entirely by local filtering no longer throws `no_stations`; the error now fires only when the upstream page itself came back short (a genuinely empty area). (#8)
- **`openchargemap_find_stations` silent undercount** — `truncated` is now computed from the raw upstream/candidate count, not the post-filter result length, so a filtered search no longer under-reports without disclosure. (#8)
- **`openchargemap_get_station_comments` rendered counts** — the header and "none carrying text" line now state their population (`2 of 6 comment(s)`) instead of conflating the returned page with `reliabilityNote`'s full-set fault ratio. (#16)
