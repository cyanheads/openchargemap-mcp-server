# 0.1.10 — 2026-10-08

## Changed

- **`@cyanheads/mcp-ts-core` `^0.13.6` → `^0.13.14`** — a tool error's text now closes with ` · request <id>` (`(reason auth_failed · not retryable · request RN9CP-542KV)`), and error envelopes carry `data.requestId` (`cyanheads/mcp-ts-core 0.13.10`).
- **Argument repair** (`cyanheads/mcp-ts-core 0.13.14`) — a numeric string for `find_stations` `latitude`, `longitude`, or `maxresults`, or for `get_station` `id`, and `null` at an optional key (`minpowerkw: null`), are accepted and repaired instead of rejected. A genuinely wrong type (`maxresults: true`) still returns `-32602`.
- **Recovery hints** — handlers and the service no longer forward `ctx.recoveryFor` hints; the framework fills each declared `errors[]` hint (`cyanheads/mcp-ts-core 0.13.10`), and the hint text callers receive is unchanged. Tests assert the declared hint through `runToolContract`.
- **Docker** — production dependencies install in a `deps` stage on `$BUILDPLATFORM`, cross-installing for the target arch (`cyanheads/mcp-ts-core 0.13.10`); that stage drops musl-only packages (`cyanheads/mcp-ts-core 0.13.11`). The new `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` run in it. Bun base images move `1.4.0` → `1.4.2`, and the image no longer sets `MCP_FORCE_CONSOLE_LOGGING`. It creates writable `.cache` and `.mirror` directories for the `bun` user.
- **`server.json`** (`cyanheads/mcp-ts-core 0.13.11` template) — the npm entries set `runtimeHint: "npx"` (was `node`) and drop the `run start:stdio` / `run start:http` package arguments; the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `"value": "http"`.
- **Packaging** — `package.json` `files` adds `!dist/*.mcpb`, keywords add `stdio` and `streamable-http`, and `packageManager` becomes `bun@1.4.2`. `.mcpbignore` adds `/docs/idea.md`, `/logs/`, `/.cache/`, `/coverage/`, and `/tests/`. `.gitignore` and `.dockerignore` ignore every `.env*` file except the templates, and `.dockerignore` also excludes the MCP Registry token files.
- **Docs** — the package description reads "from the global Open Charge Map registry" (was "via the global …") in `package.json`, `manifest.json`, both plugin manifests, and the README. The README capability reference is condensed, the MCP SDK badge moves `^2.0.0` → `^2.2.0`, the Bun badge `v1.4.0` → `v1.4.2`, and the config table gains `LOG_TOOL_FAILURE_PAYLOADS`. `.env.example` documents the framework's newer variables (`MCP_REQUEST_STATE_KEY`, `MCP_HTTP_RESUMABILITY*`, `MCP_LOG_RATE_LIMIT_*`, `LOG_TOOL_FAILURE_PAYLOADS`, and the per-signal `OTEL_EXPORTER_OTLP_*_ENDPOINT` variables) and the `127.0.0.1` HTTP host default. `CLAUDE.md` and `AGENTS.md` are synced to the 0.13.14 template.
- **Framework scripts and skills** — `devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `check-framework-antipatterns`, and `release-github` scripts and every `framework-skills/` skill are resynced to 0.13.14. The CodeQL workflow runs one analysis per language under the `/language:<language>` category.

## Fixed

- **`openchargemap_find_stations` named a nonexistent `openstreetmap_geocode` tool** in its description, its `latitude` field, and its `invalid_location` recovery hint. All three now name `openstreetmap_search_places`; `docs/design.md` matches.
